## 1. អ្វីជា Admin / General Manager?

### 1.1 និយមន័យ (Definition)

**Admin / General Manager (អភិបាលក្រុមហ៊ុន / អ្នកគ្រប់គ្រងទូទៅ)** គឺជាអ្នកដឹកនាំកំពូលប្រចាំថ្ងៃនៃស្ថាប័នអាជីវកម្ម (Tenant-Level CEO / COO / Managing Director)។ នៅក្នុងប្រព័ន្ធ DIGITECHKH BMS គាត់/នាង មិនត្រឹមតែមានតួនាទីជាអ្នកគ្រប់គ្រងយុទ្ធសាស្ត្រប៉ុណ្ណោះទេ ប៉ុន្តែជា **អ្នកចាត់ចែង និងអនុម័តប្រតិបត្តិការស្នូលទាំងអស់**៖
1. **អ្នកបញ្ជាការជួរមុខ និងជួរក្រោយ (End-to-End Orchestrator)**: តភ្ជាប់រាល់លំហូរការងាររវាងផ្នែកលក់ (Sales), ផ្នែកលទ្ធកម្ម (Procurement), ឃ្លាំងស្តុក (Warehouse), គណនេយ្យ (Finance), និងធនធានមនុស្ស (HR) ឱ្យដំណើរការស៊ីចង្វាក់គ្នាឥតខ្ចោះ។
2. **អ្នកកាន់កាប់សិទ្ធិអនុម័តខ្ពស់បំផុត (Highest Authority Sign-off)**: រាល់ការចំណាយប្រាក់ធំៗ, ការបញ្ជាទិញទំនិញលើសកម្រិត, ការបញ្ចុះតម្លៃពិសេសដល់អតិថិជនធំៗ, និងការអនុញ្ញាតឱ្យអតិថិជនជំពាក់ប្រាក់លើសពិដាន ត្រូវតែមានការយល់ព្រមពីគាត់/នាង។
3. **អ្នកគ្រប់គ្រងធនធាន និងការកំណត់ក្រុមហ៊ុន (Tenant Administrator)**: បង្កើតគណនីបុគ្គលិកថ្មី, កំណត់តួនាទី និងសិទ្ធិ, កំណត់អត្រាពន្ធសារពើពន្ធកម្ពុជា (VAT 10%, WHT), កំណត់គណនីធនាគារ និងអត្រាប្តូរប្រាក់ NBC។

## 7. តក្កវិជ្ជាអាជីវកម្ម និងកម្រិតពិដានអនុម័ត (Business Logic & Approval Thresholds)

2. **ជាមួយ Procurement Manager**:
   - អនុម័តការបញ្ជាទិញទំនិញធំៗ (PO > $1,000.00)
   - អនុម័តការជ្រើសរើស និងចុះកិច្ចសន្យាជាមួយអ្នកផ្គត់ផ្គង់យុទ្ធសាស្ត្រថ្មី
3. **ជាមួយ Warehouse Manager**:
   - អនុម័តការកាត់កងទំនិញខូចខាត ឬបាត់បង់ (Stock Write-off)
   - អនុម័តការផ្ទេរទំនិញខ្នាតធំឆ្លងសាខា
4. **ជាមួយ Chief Accountant & AP/AR Accountant**:
   - ចុះហត្ថលេខាលើប័ណ្ណចំណាយទូទាត់ប្រាក់ធំៗ (Disbursements > $500.00)
   - អនុម័តរបាយការណ៍ហិរញ្ញវត្ថុប្រចាំខែ និងការបិទគ្រាគណនេយ្យ (Financial Period Lock)
   - ពិនិត្យការអនុលោមភាពពន្ធដារ (GDT Compliance)
5. **ជាមួយ Internal Auditor**:
   - ទទួលរបាយការណ៍ស៊ើបអង្កេតករណីមិនប្រក្រតី (Red Flags Dossier)
   - ចាត់វិធានការកែតម្រូវចំពោះការបំពានច្បាប់ត្រួតពិនិត្យផ្ទៃក្នុង

## 10. ផ្ទាំងបញ្ជាការដ្ឋានប្រតិបត្តិការ (Executive Cockpit & Strategic KPIs)

```
┌────────────────────────────────────────────────────────────────────────┐
│               🏛️ ENTERPRISE EXECUTIVE COCKPIT (ADMIN / GM)             │
├──────────────────────────┬──────────────────────────┬──────────────────┤
│ ចំណូលលក់សរុប (Revenue):   │ ចំណេញសុទ្ធ (Net Profit): │ សាច់ប្រាក់ក្នុងដៃ:│
│ $68,450.00 (↑ 14.2%)     │ $14,370.00 (Margin 21%)  │ $42,180.00       │
├──────────────────────────┼──────────────────────────┼──────────────────┤
│ បំណុលត្រូវទារ (Total AR): │ បំណុលត្រូវសង (Total AP): │ សំណើរង់ចាំអនុម័ត:│

└──────────────────────────┴──────────────────────────┴──────────────────┘
```

| # | សូចនាករយុទ្ធសាស្ត្រ (Strategic KPI) | រូបមន្តគណនា | គោលដៅស្តង់ដារ | ការបកស្រាយ |
|---|---|---|:---:|---|
| 1 | **អត្រាចំណេញសុទ្ធ (Net Profit Margin %)** | $(\text{Net Profit} / \text{Revenue}) \times 100$ | $\ge 20\%$ | បង្ហាញពីប្រសិទ្ធភាពគ្រប់គ្រងចំណាយ |
| 2 | **ចរន្តសាច់ប្រាក់ទ្រទ្រង់ (Cash Runway)** | $\text{Cash Balance} / \text{Monthly Burn Rate}$ | $\ge 3$ ខែ | សុវត្ថិភាពសន្ទនីយភាពអាជីវកម្ម |
| 3 | **អត្រាបំណុលវន់ករ (Overdue AR Ratio %)** | $(\text{Overdue AR} / \text{Total AR}) \times 100$ | $< 10\%$ | ហានិភ័យបាត់បង់លំហូរសាច់ប្រាក់ |
| 4 | **ល្បឿនបង្វិលស្តុក (Inventory Turnover)** | $\text{COGS} / \text{Average Inventory Value}$ | $\ge 6$ ដង/ឆ្នាំ | ប្រសិទ្ធភាពគ្រប់គ្រងទុនស្តុក |

## 11. គំរូរចនាសម្ព័ន្ធទិន្នន័យ (Database Schema Blueprint)

```sql
-- គំរូតារាងទិន្នន័យសម្រាប់ Executive Approval & System Control Module

-- 1. តារាងសំណើអនុម័តសកល (Global Approval Requests Table)
CREATE TABLE approval_requests (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID REFERENCES tenants(id) NOT NULL,
    request_number      VARCHAR(50) UNIQUE NOT NULL, -- APP-2026-0038
    request_type        VARCHAR(50) NOT NULL, 
        -- po_approval | disbursement | high_discount | credit_override | stock_writeoff | void_invoice
    requester_id        UUID REFERENCES users(id) NOT NULL,
    target_entity_type  VARCHAR(50) NOT NULL, -- purchase_orders, disbursements, quotes, etc.
    target_entity_id    UUID NOT NULL,
    target_entity_code  VARCHAR(100), -- PO-2026-0045, QT-2026-0042
    financial_amount    DECIMAL(15,2) DEFAULT 0.00,
    discount_pct        DECIMAL(5,2),
    request_reason      TEXT NOT NULL,
    status              VARCHAR(30) DEFAULT 'pending', 
        -- pending | approved | rejected | cancelled
    approver_id         UUID REFERENCES users(id),
    decision_notes      TEXT,
    decided_at          TIMESTAMPTZ,
    created_at          TIMESTAMPTZ DEFAULT NOW(),
    updated_at          TIMESTAMPTZ DEFAULT NOW()
);

-- 2. តារាងកត់ត្រាប្រវត្តិអនុម័ត (Approval Audit Trail)
CREATE TABLE approval_logs (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    approval_request_id UUID REFERENCES approval_requests(id) ON DELETE CASCADE,
    action              VARCHAR(30) NOT NULL, -- submitted | reviewed | approved | rejected
    actor_id            UUID REFERENCES users(id) NOT NULL,
    actor_role          VARCHAR(50) NOT NULL,
    comments            TEXT,
    created_at          TIMESTAMPTZ DEFAULT NOW()
);

-- 3. តារាងបិទគ្រាគណនេយ្យ (Financial Period Locks)
CREATE TABLE financial_period_locks (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID REFERENCES tenants(id) NOT NULL,
    period_year         INT NOT NULL,
    period_month        INT NOT NULL, -- 1 to 12
    is_locked           BOOLEAN DEFAULT TRUE,
    locked_by_user_id   UUID REFERENCES users(id) NOT NULL, -- GM User ID
    locked_at           TIMESTAMPTZ DEFAULT NOW(),
    unlock_reason       TEXT,
    unlocked_at         TIMESTAMPTZ,
    unlocked_by_user_id UUID REFERENCES users(id),
    UNIQUE(tenant_id, period_year, period_month)
);

-- 4. តារាងកំណត់ដែនពិដានអនុម័តរបស់ក្រុមហ៊ុន (Tenant Approval Thresholds)
CREATE TABLE tenant_approval_thresholds (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id           UUID REFERENCES tenants(id) UNIQUE NOT NULL,
    po_gm_threshold     DECIMAL(15,2) DEFAULT 1000.00,
    disbursement_gm_threshold DECIMAL(15,2) DEFAULT 500.00,
    discount_gm_threshold_pct DECIMAL(5,2) DEFAULT 10.00,
    writeoff_gm_threshold DECIMAL(15,2) DEFAULT 200.00,
    updated_by          UUID REFERENCES users(id),
    updated_at          TIMESTAMPTZ DEFAULT NOW()
);
```

## 12. អភិបាលកិច្ច និងសុវត្ថិភាពទិន្នន័យ (Governance & Anti-Fraud Controls)

ដើម្បីការពារអភិបាលកិច្ចក្រុមហ៊ុន និងបញ្ចៀសការរំលោភអំណាច ប្រព័ន្ធអនុវត្តគោលការណ៍គ្រឹះចំនួន 4៖

1. **គោលការណ៍ត្រួតពិនិត្យទ្វេភាគី (Dual-Control on Extreme Payouts)**:
   - ចំពោះការបើកសាច់ប្រាក់ធំៗលើសពី `$5,000.00` ទោះបីជា GM ចុះហត្ថលេខារួចហើយក៏ដោយ ប្រព័ន្ធតម្រូវឱ្យមានការបញ្ជាក់ហត្ថលេខាឌីជីថលបន្ថែមពី **Chief Accountant** ឬ **Board Member** ដើម្បីការពារការកិបកេងសាច់ប្រាក់ឯកតោភាគី។
2. **ភាពមិនអាចកែប្រែកំណត់ហេតុ (Audit Trail Immutability)**:
   - រាល់ពេលដែល GM ចុច «អនុម័ត», «បដិសេធ», «ចាក់សោរគ្រាហិរញ្ញវត្ថុ», ឬ «Override» ប្រព័ន្ធកត់ត្រាក្នុងតារាង `global_audit_trails` ភ្លាមៗជាមួយ IP Address និង Timestamp ដែលមិនអាចលុបបានឡើយ។
3. **ការទប់ស្កាត់ការកែប្រែទិន្នន័យក្នុងគ្រាចាក់សោរ (Locked Period Immutability Guard)**:
   - នៅពេលខែណាមួយត្រូវបានចាក់សោរ (Period Locked) សូម្បីតែ GM ផ្ទាល់ក៏មិនអាចចុចបង្កើត ឬកែសម្រួលវិក្កយបត្រក្នុងខែនោះបានដែរ។ ប្រសិនបើតម្រូវឱ្យកែប្រែដោយសារសវនកម្ម GM ត្រូវចុច «ស្នើសុំដោះសោរបណ្តោះអាសន្ន» ដោយមានកំណត់ត្រាមូលហេតុច្បាស់លាស់។
4. **ការការពារការបែកធ្លាយទិន្នន័យឆ្លងក្រុមហ៊ុន (Strict Multi-Tenant Isolation)**:
   - គណនី GM ត្រូវបានកំណត់សិទ្ធិយ៉ាងតឹងរ៉ឹងដោយ Row-Level Security (RLS) ត្រឹមតែ `tenant_id` របស់ខ្លួនប៉ុណ្ណោះ មិនអាចទាញយកទិន្នន័យរបស់ក្រុមហ៊ុនដៃគូ ឬក្រុមហ៊ុនបុត្រសម្ព័ន្ធដទៃឡើយ។

## 14. សំណួរ និងចម្លើយទូទៅ (FAQ)

**Q: តើអ្វីជាភាពខុសគ្នាសំខាន់រវាង Admin / General Manager និង Super Admin?**  
A: Super Admin គឺជាអ្នកគ្រប់គ្រងប្រព័ន្ធបច្ចេកវិទ្យាកម្រិត Platform (Multi-Tenant Infrastructure) ដែលមើលការខុសត្រូវលើក្រុមហ៊ុនរាប់សិបនៅក្នុងប្រព័ន្ធ Cloud។ ចំណែក Admin / General Manager គឺជាមេដឹកនាំកំពូលនៃក្រុមហ៊ុនអាជីវកម្មជាក់លាក់មួយ (Single Tenant) ដែលមានសិទ្ធិប្រតិបត្តិការ និងអនុម័តអាជីវកម្មពេញលេញក្នុងក្រុមហ៊ុនរបស់ខ្លួន ប៉ុន្តែមិនអាចលូកដៃទៅកាន់ក្រុមហ៊ុនដទៃបានឡើយ។

**Q: ហេតុអ្វីបានជាត្រូវមានពិដានអនុម័ត (Approval Thresholds) សម្រាប់ GM?**  
A: ប្រសិនបើរាល់ការចំណាយ និងវិក្កយបត្រទាំងអស់ត្រូវរង់ចាំ GM អនុម័ត នោះអាជីវកម្មនឹងកកស្ទះ និងយឺតយ៉ាវយ៉ាងខ្លាំង (Bottleneck)។ ការកំណត់ពិដានអនុញ្ញាតឱ្យ Department Managers (Sales, Procurement, Accounting) សម្រេចចិត្តលើប្រតិបត្តិការតូចៗប្រចាំថ្ងៃ (ឧ. ចំណាយ $\le \$500.00$) ហើយទុកតែប្រតិបត្តិការធំៗ ឬមានហានិភ័យខ្ពស់ជូន GM ពិនិត្យប៉ុណ្ណោះ។

**Q: តើ GM អាចលុបវិក្កយបត្រដែលបានប្រកាសពន្ធរួចហើយបានទេ?**  
A: **មិនអាចលុបបានឡើយ**។ ប្រសិនបើខែនោះត្រូវបានចាក់សោរគ្រាហិរញ្ញវត្ថុ (Period Locked) ប្រព័ន្ធនឹងរារាំងមិនឱ្យមានការកែប្រែ ឬលុបជាដាច់ខាត ដើម្បីការពារកុំឱ្យក្រុមហ៊ុនរងការពិន័យពីអគ្គនាយកដ្ឋានពន្ធដារ (GDT)។ ប្រសិនបើមានកំហុសឆ្គង ត្រូវដោះស្រាយតាមរយៈការចេញ **Credit Note** ក្នុងខែបន្ទាប់។

**Q: តើ GM អាចផ្ទេរសិទ្ធិអនុម័តឱ្យអ្នកដទៃបានទេ ពេលទៅបេសកកម្មក្រៅប្រទេស?**  
A: បាន។ ប្រព័ន្ធមានមុខងារ «ផ្ទេរសិទ្ធិអនុម័តបណ្តោះអាសន្ន (Temporary Approval Delegation)» ដែល GM អាចកំណត់ផ្ទេរសិទ្ធិឱ្យ Deputy GM ឬ Chief Accountant ក្នុងចន្លោះកាលបរិច្ឆេទជាក់លាក់មួយ ដោយមានកំណត់ត្រាត្រួតពិនិត្យច្បាស់លាស់។
