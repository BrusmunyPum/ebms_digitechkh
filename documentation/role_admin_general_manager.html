អនុម័តការលើកលែងពិដានឥណទាន (Credit Override) ✅ សិទ្ធិអនុម័តកំពូល សម្រេចចិត្តអនុញ្ញាតឱ្យអតិថិជនជំពាក់លើសកម្រិត
អនុម័តការកាត់កងទំនិញខូចខាត (Stock Write-off) ✅ សិទ្ធិអនុម័តកំពូល កត់ត្រាការខាតបង់ទ្រព្យសកម្ម និងទទួលស្គាល់ការបាត់បង់
បិទ ឬបើកគ្រាគណនេយ្យ (Financial Period Lock) ✅ សិទ្ធិអនុម័តកំពូល ចាក់សោរទិន្នន័យខែចាស់ការពារការកែប្រែតួលេខសារពើពន្ធ

1. អ្វីជា Admin / General Manager? #

1.1 និយមន័យ (Definition) #

Admin / General Manager (អភិបាលក្រុមហ៊ុន / អ្នកគ្រប់គ្រងទូទៅ) គឺជាអ្នកដឹកនាំកំពូលប្រចាំថ្ងៃនៃស្ថាប័នអាជីវកម្ម (Tenant-Level CEO / COO / Managing Director)។ នៅក្នុងប្រព័ន្ធ DIGITECHKH BMS គាត់/នាង មិនត្រឹមតែមានតួនាទីជាអ្នកគ្រប់គ្រងយុទ្ធសាស្ត្រប៉ុណ្ណោះទេ ប៉ុន្តែជា អ្នកចាត់ចែង និងអនុម័តប្រតិបត្តិការស្នូលទាំងអស់៖

  1. អ្នកបញ្ជាការជួរមុខ និងជួរក្រោយ (End-to-End Orchestrator): តភ្ជាប់រាល់លំហូរការងាររវាងផ្នែកលក់ (Sales), ផ្នែកលទ្ធកម្ម (Procurement), ឃ្លាំងស្តុក (Warehouse), គណនេយ្យ (Finance), និងធនធានមនុស្ស (HR) ឱ្យដំណើរការស៊ីចង្វាក់គ្នាឥតខ្ចោះ។
  2. អ្នកកាន់កាប់សិទ្ធិអនុម័តខ្ពស់បំផុត (Highest Authority Sign-off): រាល់ការចំណាយប្រាក់ធំៗ, ការបញ្ជាទិញទំនិញលើសកម្រិត, ការបញ្ចុះតម្លៃពិសេសដល់អតិថិជនធំៗ, និងការអនុញ្ញាតឱ្យអតិថិជនជំពាក់ប្រាក់លើសពិដាន ត្រូវតែមានការយល់ព្រមពីគាត់/នាង។
  3. អ្នកគ្រប់គ្រងធនធាន និងការកំណត់ក្រុមហ៊ុន (Tenant Administrator): បង្កើតគណនីបុគ្គលិកថ្មី, កំណត់តួនាទី និងសិទ្ធិ, កំណត់អត្រាពន្ធសារពើពន្ធកម្ពុជា (VAT 10%, WHT), កំណត់គណនីធនាគារ និងអត្រាប្តូរប្រាក់ NBC។

1.2 ការប្រៀបធៀបរវាង Super Admin, Admin / GM, និង Internal Auditor #

លក្ខខណ្ឌប្រៀបធៀប Super Admin (អ្នកគ្រប់គ្រងប្រព័ន្ធមេ) Admin / GM (អភិបាលក្រុមហ៊ុន) Internal Auditor / Exec (សវនករផ្ទៃក្នុង)
វិសាលភាពក្រុមហ៊ុន មើលឃើញគ្រប់ក្រុមហ៊ុនទាំងអស់ (Multi-Tenant) ចាក់សោរត្រឹមក្រុមហ៊ុនរបស់ខ្លួន (Single Tenant) ចាក់សោរត្រឹមក្រុមហ៊ុនរបស់ខ្លួន (Single Tenant)
សិទ្ធិប្រតិបត្តិការ គ្រប់គ្រង Subscription, DB, System Tenants Full CRUD ប្រតិបត្តិការអាជីវកម្មទាំងអស់ Strict Read-Only 100% (គ្មានសិទ្ធិកែ/បង្កើត)
សិទ្ធិអនុម័ត (Approval) គ្មានសិទ្ធិលូកដៃក្នុងអាជីវកម្មរបស់ក្រុមហ៊ុនឡើយ ជាអ្នកចុះហត្ថលេខាអនុម័តចុងក្រោយ គ្មានសិទ្ធិអនុម័តឡើយ (ត្រួតពិនិត្យអព្យាក្រឹត)
ការកំណត់គណនីបុគ្គលិក បង្កើត Company Tenant និង Root Admin បង្កើត និងចាត់ចែងបុគ្គលិកទាំងអស់ក្នុងក្រុមហ៊ុន គ្មានសិទ្ធិបង្កើត ឬកែប្រែគណនីបុគ្គលិកឡើយ
ការបិទគ្រាគណនេយ្យ គ្មានសិទ្ធិ ជាអ្នកចុះហត្ថលេខាបិទគ្រាហិរញ្ញវត្ថុផ្លូវការ ត្រួតពិនិត្យផ្ទៀងផ្ទាត់ភាពត្រឹមត្រូវនៃតួលេខ

3. អ្វីដែល Admin / GM ធ្វើបាន និងហាមធ្វើ (Full Capability Map) #

3.1 ✅ អ្វីដែល Admin / GM ធ្វើបានពេញលេញ #

# សមត្ថភាពស្នូល ពិពណ៌នា និងករណីប្រើប្រាស់
1 អនុម័តសំណើហិរញ្ញវត្ថុ និងប្រតិបត្តិការគ្រប់ប្រភេទ អនុម័ត PO > $1,000, Disbursement > $500, Discount > 10%, Credit Override, Stock Adjustment
2 បង្កើត កែប្រែ និងពិនិត្យឯកសារគ្រប់ម៉ូឌុល (Full CRUD) មានសិទ្ធិចូលទៅកាន់គ្រប់ទំព័រក្នុង 3-sales/, 4-buy/, 5-stock/, 6-reports/
3 គ្រប់គ្រងគណនីបុគ្គលិក និងកំណត់សិទ្ធិ (User Management) បង្កើតបុគ្គលិកថ្មី, កំណត់ Role, កំណត់សាខា, ប្តូរលេខកូដសម្ងាត់, និងចាក់សោរគណនីពេលឈប់
4 គ្រប់គ្រងការកំណត់ក្រុមហ៊ុន (Company Settings) កែប្រែឈ្មោះក្រុមហ៊ុន, ឡូហ្គោ, អាសយដ្ឋាន, លេខ VATTIN, គណនីធនាគារ KHQR
5 កំណត់អត្រាពន្ធ និងអត្រាប្តូរប្រាក់ (Tax & Currency Rates) កំណត់ VAT 10%, WHT (15%/10%), និងអត្រាប្តូរប្រាក់ផ្លូវការ USD/KHR
6 បិទគ្រាគណនេយ្យប្រចាំខែ/ប្រចាំឆ្នាំ (Period Lock) ចាក់សោរឯកសារហិរញ្ញវត្ថុនៃខែដែលបានរាយការណ៍ពន្ធរួច ការពារការកែប្រែតួលេខ
7 អនុម័តការលុបចោលវិក្កយបត្រជាផ្លូវការ (Void Invoices) អនុម័តការលុបវិក្កយបត្រដែលចេញខុស ដោយតម្រូវឱ្យមានកំណត់ត្រាមូលហេតុច្បាស់លាស់
8 មើលរបាយការណ៍ផលចំណេញ និងសុខភាពហិរញ្ញវត្ថុ 360° P&L, Balance Sheet, Cash Flow, AR/AP Aging, Stock Valuation, Sales Performance
9 បោះពុម្ព និងទាញយករបាយការណ៍សហគ្រាសកម្រិត A4 ទាញយក និងបោះពុម្ពរបាយការណ៍ផ្លូវការសម្រាប់ដាក់ជូនក្រុមប្រឹក្សាភិបាល ឬធនាគារ

3.2 ❌ អ្វីដែល Admin / GM ហាមធ្វើដាច់ខាត #

# សកម្មភាពហាមឃាត់ ហានិភ័យ និងហេតុផលការពារ
1 ❌ ចូលមើល ឬកែប្រែទិន្នន័យរបស់ក្រុមហ៊ុនផ្សេងទៀត បំពានលើគោលការណ៍ Multi-Tenant Data Isolation និងច្បាប់រក្សាការសម្ងាត់
2 ❌ កែប្រែ ឬលុបកំណត់ហេតុសវនកម្ម (Audit Trails) កំណត់ហេតុជាប្រវត្តិសាស្ត្ររឹងមាំ (Immutable) ហាមកែប្រែជាដាច់ខាត
3 ❌ កែប្រែលេខកូដប្រព័ន្ធ ឬរចនាសម្ព័ន្ធ Server Database ភារកិច្ចផ្តាច់មុខរបស់ក្រុមបច្ចេកទេស និង Super Admin
4 ❌ លុបទិន្នន័យគណនីដែលមានប្រតិបត្តិការហិរញ្ញវត្ថុរួចហើយ រក្សាភាពសុចរិតនៃទិន្នន័យគណនេយ្យ និងការផ្ទៀងផ្ទាត់សវនកម្ម
5 ❌ អនុម័តប័ណ្ណចំណាយទូទាត់ប្រាក់ឱ្យខ្លួនឯងដោយគ្មានសាក្សី គោលការណ៍ Dual-Control: ការបើកលុយធំៗត្រូវមាន Chief Accountant ត្រួតពិនិត្យ

# សូចនាករយុទ្ធសាស្ត្រ (Strategic KPI) រូបមន្តគណនា គោលដៅស្តង់ដារ ការបកស្រាយ
1 អត្រាចំណេញសុទ្ធ (Net Profit Margin %) $(\text{Net Profit} / \text{Revenue}) \times 100$ $\ge 20%$ បង្ហាញពីប្រសិទ្ធភាពគ្រប់គ្រងចំណាយ
2 ចរន្តសាច់ប្រាក់ទ្រទ្រង់ (Cash Runway) $\text{Cash Balance} / \text{Monthly Burn Rate}$ $\ge 3$ ខែ សុវត្ថិភាពសន្ទនីយភាពអាជីវកម្ម
3 អត្រាបំណុលវន់ករ (Overdue AR Ratio %) $(\text{Overdue AR} / \text{Total AR}) \times 100$ $< 10%$ ហានិភ័យបាត់បង់លំហូរសាច់ប្រាក់
4 ល្បឿនបង្វិលស្តុក (Inventory Turnover) $\text{COGS} / \text{Average Inventory Value}$ $\ge 6$ ដង/ឆ្នាំ ប្រសិទ្ធភាពគ្រប់គ្រងទុនស្តុក
5 ល្បឿនដោះស្រាយការអនុម័ត (Approval SLA) ពេលវេលាមធ្យមពីពេលស្នើសុំដល់ពេលចុះហត្ថលេខា $< 4$ ម៉ោង កុំឱ្យកកស្ទះប្រតិបត្តិការជួរមុខ

ដើម្បីការពារអភិបាលកិច្ចក្រុមហ៊ុន និងបញ្ចៀសការរំលោភអំណាច ប្រព័ន្ធអនុវត្តគោលការណ៍គ្រឹះចំនួន 4៖

  1. គោលការណ៍ត្រួតពិនិត្យទ្វេភាគី (Dual-Control on Extreme Payouts):
    • ចំពោះការបើកសាច់ប្រាក់ធំៗលើសពី $5,000.00 ទោះបីជា GM ចុះហត្ថលេខារួចហើយក៏ដោយ ប្រព័ន្ធតម្រូវឱ្យមានការបញ្ជាក់ហត្ថលេខាឌីជីថលបន្ថែមពី Chief Accountant ឬ Board Member ដើម្បីការពារការកិបកេងសាច់ប្រាក់ឯកតោភាគី។
  2. ភាពមិនអាចកែប្រែកំណត់ហេតុ (Audit Trail Immutability):
    • រាល់ពេលដែល GM ចុច «អនុម័ត», «បដិសេធ», «ចាក់សោរគ្រាហិរញ្ញវត្ថុ», ឬ «Override» ប្រព័ន្ធកត់ត្រាក្នុងតារាង global_audit_trails ភ្លាមៗជាមួយ IP Address និង Timestamp ដែលមិនអាចលុបបានឡើយ។
  3. ការទប់ស្កាត់ការកែប្រែទិន្នន័យក្នុងគ្រាចាក់សោរ (Locked Period Immutability Guard):
    • នៅពេលខែណាមួយត្រូវបានចាក់សោរ (Period Locked) សូម្បីតែ GM ផ្ទាល់ក៏មិនអាចចុចបង្កើត ឬកែសម្រួលវិក្កយបត្រក្នុងខែនោះបានដែរ។ ប្រសិនបើតម្រូវឱ្យកែប្រែដោយសារសវនកម្ម GM ត្រូវចុច «ស្នើសុំដោះសោរបណ្តោះអាសន្ន» ដោយមានកំណត់ត្រាមូលហេតុច្បាស់លាស់។
  4. ការការពារការបែកធ្លាយទិន្នន័យឆ្លងក្រុមហ៊ុន (Strict Multi-Tenant Isolation):
    • គណនី GM ត្រូវបានកំណត់សិទ្ធិយ៉ាងតឹងរ៉ឹងដោយ Row-Level Security (RLS) ត្រឹមតែ tenant_id របស់ខ្លួនប៉ុណ្ណោះ មិនអាចទាញយកទិន្នន័យរបស់ក្រុមហ៊ុនដៃគូ ឬក្រុមហ៊ុនបុត្រសម្ព័ន្ធដទៃឡើយ។

13.1 អនុសាសន៍រចនាប្រព័ន្ធ (Architectural Recommendations) #

✅ ណែនាំ 1: Centralized Actionable Approvals Hub #

នៅក្នុងទំព័រ approvals.html ត្រូវរៀបចំជា Tabs បែងចែកតាមប្រភេទការងារ (PO, ប័ណ្ណចំណាយ, បញ្ចុះតម្លៃ, ពិដានបំណុល) ជាមួយ Badge បង្ហាញចំនួនរង់ចាំភ្លាមៗ ដើម្បីកុំឱ្យ GM ពិបាករុករក។

✅ ណែនាំ 2: One-Click Instant Decision with Confirmation Toast #

នៅក្នុងទំព័រ view-approval.html ប៊ូតុង «អនុម័ត» និង «បដិសេធ» ត្រូវភ្ជាប់ជាមួយ Custom Confirmation Modal (showCustomConfirm()) ដើម្បីការពារការច្រឡំដៃ ហើយនៅពេលជោគជ័យត្រូវលោត Toast ពណ៌បៃតងស្រស់ស្អាត (showToast("សំណើត្រូវបានអនុម័តដោយជោគជ័យ!", "success"))។

✅ ណែនាំ 3: Real-Time Cash Runway Alert #

នៅលើ dashboard.html ត្រូវមាន Widget គណនា Cash Runway៖ ប្រសិនបើសាច់ប្រាក់ធនាគារសរុបទាបជាងចំណាយប្រតិបត្តិការ 2 ខែ ត្រូវបង្ហាញ Warning Alert ពណ៌ទឹកក្រូចដើម្បីឱ្យ GM ចាត់វិធានការពន្លឿនការទារបំណុលអតិថិជន។

13.2 បញ្ជីត្រួតពិនិត្យការសាងសង់ Prototype (15-Point Prototype Checklist) #

មុនពេលចាត់ទុកថា Prototype សម្រាប់ Admin / General Manager ត្រឹមត្រូវ 100% ត្រូវផ្ទៀងផ្ទាត់៖

  • កម្ពស់ Header ស្មើគ្នា: ទាំង Sidebar Brand និង Content Top Header មានកម្ពស់ h-[72px] ស្មើគ្នាបេះបិទ។
  • ភាសាខ្មែរសុទ្ធសាធ 100%: គ្មានពាក្យអង់គ្លេសលាយឡំលើ UI, ប៊ូតុង, តារាង, ផ្លាក Badge ឬ Toast ឡើយ។
  • លេខអង់គ្លេស 0-9: គ្រប់កាលបរិច្ឆេទ, ភាគរយ, លេខកូដ (#APP-2026-0038, #PO-2026-0045), និងទឹកប្រាក់ ប្រើលេខ 0-9 ជានិច្ច។
  • គ្មាន Pop-up Modal សម្រាប់ View Detail: ទំព័រ view-approval.html ជាទំព័រពេញលេញ (Dedicated Full Page)។
  • ប៊ូតុងត្រឡប់ក្រោយស្តង់ដារ: ប្រអប់មូលកោង w-10 h-10 rounded-xl bg-slate-50 border border-slate-200/70 មានតែរូបព្រួញ។
  • គ្មាន Native Select: ប្រើ Custom Dropdown មាន Stacking Context z-50 ត្រឹមត្រូវ។

  • ប្លង់ពេញទទឹង: <main class="w-full"> គ្មានការប្រើ max-w-7xl mx-auto។

14. សំណួរ និងចម្លើយទូទៅ (FAQ) #

Q: តើអ្វីជាភាពខុសគ្នាសំខាន់រវាង Admin / General Manager និង Super Admin?
A: Super Admin គឺជាអ្នកគ្រប់គ្រងប្រព័ន្ធបច្ចេកវិទ្យាកម្រិត Platform (Multi-Tenant Infrastructure) ដែលមើលការខុសត្រូវលើក្រុមហ៊ុនរាប់សិបនៅក្នុងប្រព័ន្ធ Cloud។ ចំណែក Admin / General Manager គឺជាមេដឹកនាំកំពូលនៃក្រុមហ៊ុនអាជីវកម្មជាក់លាក់មួយ (Single Tenant) ដែលមានសិទ្ធិប្រតិបត្តិការ និងអនុម័តអាជីវកម្មពេញលេញក្នុងក្រុមហ៊ុនរបស់ខ្លួន ប៉ុន្តែមិនអាចលូកដៃទៅកាន់ក្រុមហ៊ុនដទៃបានឡើយ។

Q: ហេតុអ្វីបានជាត្រូវមានពិដានអនុម័ត (Approval Thresholds) សម្រាប់ GM?
A: ប្រសិនបើរាល់ការចំណាយ និងវិក្កយបត្រទាំងអស់ត្រូវរង់ចាំ GM អនុម័ត នោះអាជីវកម្មនឹងកកស្ទះ និងយឺតយ៉ាវយ៉ាងខ្លាំង (Bottleneck)។ ការកំណត់ពិដានអនុញ្ញាតឱ្យ Department Managers (Sales, Procurement, Accounting) សម្រេចចិត្តលើប្រតិបត្តិការតូចៗប្រចាំថ្ងៃ (ឧ. ចំណាយ $\le $500.00$) ហើយទុកតែប្រតិបត្តិការធំៗ ឬមានហានិភ័យខ្ពស់ជូន GM ពិនិត្យប៉ុណ្ណោះ។

Q: តើ GM អាចលុបវិក្កយបត្រដែលបានប្រកាសពន្ធរួចហើយបានទេ?
A: មិនអាចលុបបានឡើយ។ ប្រសិនបើខែនោះត្រូវបានចាក់សោរគ្រាហិរញ្ញវត្ថុ (Period Locked) ប្រព័ន្ធនឹងរារាំងមិនឱ្យមានការកែប្រែ ឬលុបជាដាច់ខាត ដើម្បីការពារកុំឱ្យក្រុមហ៊ុនរងការពិន័យពីអគ្គនាយកដ្ឋានពន្ធដារ (GDT)។ ប្រសិនបើមានកំហុសឆ្គង ត្រូវដោះស្រាយតាមរយៈការចេញ Credit Note ក្នុងខែបន្ទាប់។

Q: តើ GM អាចផ្ទេរសិទ្ធិអនុម័តឱ្យអ្នកដទៃបានទេ ពេលទៅបេសកកម្មក្រៅប្រទេស?
A: បាន។ ប្រព័ន្ធមានមុខងារ «ផ្ទេរសិទ្ធិអនុម័តបណ្តោះអាសន្ន (Temporary Approval Delegation)» ដែល GM អាចកំណត់ផ្ទេរសិទ្ធិឱ្យ Deputy GM ឬ Chief Accountant ក្នុងចន្លោះកាលបរិច្ឆេទជាក់លាក់មួយ ដោយមានកំណត់ត្រាត្រួតពិនិត្យច្បាស់លាស់។
