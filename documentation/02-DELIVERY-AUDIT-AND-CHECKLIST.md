## 2. បញ្ជីត្រួតពិនិត្យការអនុលោមតាមស្តង់ដារ (Mandatory Standards Checklist)

- [x] **ស្តង់ដារភាសាខ្មែរសុទ្ធសាធ 100% (Rule 1)**៖ គ្មានពាក្យអង់គ្លេសលាយឡំ ឬពាក្យក្នុងរង្វង់ក្រចកជាភាសាអង់គ្លេសលើ UI ឡើយ។
- [x] **ស្តង់ដារលេខអង់គ្លេស/អារ៉ាប់ (`0-9`) (Rule 1)**៖ រាល់លេខទាំងអស់ (កាលបរិច្ឆេទ, តម្លៃ, លេខកូដ, ចំនួន, លេខទូរស័ព្ទ) ប្រើប្រាស់ `0-9` ជានិច្ច។
- [x] **ស្តង់ដារកម្ពស់ក្បាលទំព័រ និង Sidebar (Rule 2)**៖ ទាំងក្បាល Sidebar និង Content Header មានកម្ពស់ថេរ `h-[72px] px-6 flex-shrink-0` ដូចគ្នា 100% បន្ទាត់ខណ្ឌរត់ត្រង់ស្មើល្អឥតខ្ចោះ។
- [x] **ស្តង់ដារទំព័រពេញលេញសម្រាប់ Add/Edit/View (Rule 5)**៖ គ្មានការប្រើប្រាស់ Pop-up Modal សម្រាប់ទម្រង់បង្កើតថ្មី ឬមើលលម្អិតឡើយ (ទំព័រទាំងអស់ជា Dedicated Full Page)។
- [x] **ស្តង់ដារប៊ូតុងត្រឡប់ក្រោយរួម (Rule 5)**៖ គ្រប់ទំព័ររងទាំងអស់ប្រើប្រាស់ប៊ូតុងត្រឡប់ក្រោយប្រអប់មូលកោងមានរូបព្រួញតែមួយគត់ `w-10 h-10 rounded-xl bg-slate-50 border border-slate-200/70`។
- [x] **ស្តង់ដារគ្មាន Browser Native UI (Rule 6)**៖ គ្មានការប្រើ native `<select>`, `alert()`, `confirm()` ឡើយ។
- [x] **ស្តង់ដារការពារការលេចធ្លាយតម្លៃ (Zero Price Leakage - Rule 10)**៖ បុគ្គលិកស្តុក និងអ្នកដឹកជញ្ជូន មិនឃើញថ្លៃដើម ឬតម្លៃលក់ឡើយ។
- [x] **ស្តង់ដារបោះពុម្ពផ្លូវការ A4 (Rule 12)**៖ វិក្កយបត្រ ប័ណ្ណចំណាយ ប័ណ្ណបើកប្រាក់ខែ គាំទ្រការបោះពុម្ព A4 ស្អាតបរិសុទ្ធ លាក់ UI មិនពាក់ព័ន្ធស្វ័យប្រវត្តិ។
- [x] **ការត្រួតពិនិត្យតំណភ្ជាប់ (Link Verification)**៖ 695 References ត្រូវបានផ្ទៀងផ្ទាត់ដោយស្វ័យប្រវត្តិ → **0 Broken References**។

## 3. បញ្ជីត្រួតពិនិត្យការដាក់ឱ្យដំណើរការផ្លូវការ (Enterprise Deployment & Handover Checklist)

### ដំណាក់កាល D-30៖ ការរៀបចំទិន្នន័យ និងបរិស្ថានប្រព័ន្ធ (Data Migration & Setup)
- [ ] ផ្ទេរទិន្នន័យអតិថិជន និងអ្នកផ្គត់ផ្គង់ពីសៀវភៅចាស់ ឬឯកសារចាស់ចូលក្នុងប្រព័ន្ធ
- [ ] ចុះបញ្ជីមុខទំនិញទាំងអស់ រួមទាំងរូបភាព កូដបាកូដ និងឯកតារាប់
- [ ] កំណត់សិទ្ធិប្រើប្រាស់ និងបង្កើតគណនីបុគ្គលិកតាមតួនាទីទាំង 12 ដោយគ្មានការជាន់សិទ្ធិ
- [ ] កំណត់រូបិយប័ណ្ណគោល (ប្រាក់រៀល និងប្រាក់ដុល្លារ) ព្រមទាំងអត្រាប្តូរប្រាក់ផ្លូវការ
- [ ] កំណត់ពន្ធអាករលើតម្លៃបន្ថែម (អតប 10%) តាមច្បាប់សារពើពន្ធកម្ពុជា
- [ ] កំណត់ទីតាំងឃ្លាំង និងសាខាទាំងអស់ក្នុងប្រព័ន្ធ

### ដំណាក់កាល D-7៖ ការធ្វើតេស្តសាកល្បង និងឧបករណ៍រឹង (Hardware & Integration Testing)
- [ ] ភ្ជាប់ និងធ្វើតេស្តម៉ាស៊ីនស្កេនបាកូដជាមួយកុំព្យូទ័រ និងថេបប្លេត
- [ ] ធ្វើតេស្តម៉ាស៊ីនព្រីនវិក្កយបត្រកម្ដៅ 80 មីលីម៉ែត្រ (អក្សរខ្មែរច្បាស់ មិនបែក)
- [ ] ធ្វើតេស្តការទូទាត់ប្រាក់តាមកូដស្កេនបាគង ខេអេចឃ្យូអរ ឌីណាមិក (ទាំងប្រាក់ដុល្លារ និងរៀល)
- [ ] ធ្វើតេស្តការលក់ក្រៅបណ្តាញ (ផ្តាច់ខ្សែអ៊ីនធឺណិត និងបិទវ៉ាយហ្វាយ)
- [ ] ធ្វើតេស្តការផ្ញើសារជូនដំណឹងលក់ និងបិទវេនប្រាក់ស្វ័យប្រវត្តិតាមតេឡេក្រាម
- [ ] ធ្វើតេស្តការបោះពុម្ពឯកសារផ្លូវការ A4 (វិក្កយបត្រ ប័ណ្ណចំណាយ ប័ណ្ណបើកប្រាក់ខែ)

### ដំណាក់កាល D-1៖ ការផ្ទៀងផ្ទាត់ចុងក្រោយ និងការបណ្តុះបណ្តាល (Final Readiness & Training)
- [ ] បណ្តុះបណ្តាលបុគ្គលិកគិតលុយ (POS) អំពីរបៀបបើកវេន គិតលុយ និងបិទវេន (Z-Report)
- [ ] បណ្តុះបណ្តាលបុគ្គលិកលក់អំពីការបង្កើតសម្រង់តម្លៃ និងវិក្កយបត្រ
- [ ] បណ្តុះបណ្តាលបុគ្គលិកឃ្លាំងអំពីការទទួលទំនិញចូល និងផ្ទេរស្តុក (លាក់តម្លៃទិញ)
- [ ] សម្អាតទិន្នន័យតេស្តទាំងអស់ចេញពីប្រព័ន្ធ ដើម្បីចាប់ផ្តើមទិន្នន័យពិតប្រាកដ
- [ ] បង្កើតច្បាប់ចម្លងបម្រុងទុកមូលដ្ឋានទិន្នន័យដំបូង (Initial Clean Backup)
- [ ] រាប់ និងផ្ទៀងផ្ទាត់សាច់ប្រាក់ដើមគ្រាក្នុងថតប្រាក់

### ដំណាក់កាល D-0៖ ថ្ងៃបើកដំណើរការដំបូង (Go-Live Execution)
- [ ] ក្រុមការងារបច្ចេកទេសប្រចាំការផ្ទាល់នៅកន្លែងអាជីវកម្មរបស់អតិថិជន
- [ ] ត្រួតពិនិត្យប្រតិបត្តិការលក់ 5 វិក្កយបត្រដំបូងយ៉ាងម៉ឺងម៉ាត់
- [ ] ផ្ទៀងផ្ទាត់ការកាត់ស្តុកជាក់ស្តែងក្រោយពេលលក់
- [ ] ផ្ទៀងផ្ទាត់ការទូទាត់ប្រាក់តាមបាគងចូលគណនីធនាគារពិតប្រាកដ
- [ ] ត្រួតពិនិត្យការបិទវេនសាច់ប្រាក់ចុងក្រោយ និងផ្ទៀងផ្ទាត់របាយការណ៍បិទវេន Z-Report

### ដំណាក់កាល T+30៖ ការវាយតម្លៃ និងស្ថិរភាពរយៈពេលវែង (Stabilization & Audit)
- [ ] រាប់ស្តុកជាក់ស្តែងធៀបនឹងតួលេខក្នុងប្រព័ន្ធ (Stock Reconciliation)
- [ ] ត្រួតពិនិត្យរបាយការណ៍ចំណេញខាតប្រចាំខែដំបូងជាមួយម្ចាស់អាជីវកម្ម
- [ ] វាយតម្លៃកម្រិតនៃការទប់ស្កាត់ការលេចធ្លាយ និងកំហុសទិន្នន័យ
- [ ] ប្រមូលមតិកែលម្អពីបុគ្គលិក និងរៀបចំការបណ្តុះបណ្តាលបំប៉នបន្ថែម

## 4. អនុសាសន៍របស់អ្នកជំនាញ (Expert Recommendations)

### 1. អនុសាសន៍ផ្នែកស្ថាបត្យកម្មបច្ចេកវិទ្យា (Architecture & Technology)
- **ការបម្រុងទុកទិន្នន័យស្វ័យប្រវត្តិ**៖ ត្រូវកំណត់ការចម្លងទិន្នន័យបម្រុងទុកស្វ័យប្រវត្តិយ៉ាងហោចណាស់ 2 ដងក្នុងមួយថ្ងៃ (ពេលថ្ងៃត្រង់ និងពាក់កណ្តាលអធ្រាត្រ) ទៅកាន់ប្រព័ន្ធផ្ទុកទិន្នន័យដាច់ដោយឡែក។
- **ការការពារការលេចធ្លាយទិន្នន័យក្រុមហ៊ុន**៖ ត្រូវប្រើប្រាស់លេខកូដសម្គាល់ក្រុមហ៊ុនដាច់ដោយឡែកក្នុងគ្រប់សំណួរទិន្នន័យទាំងអស់ ដើម្បីធានាថាក្រុមហ៊ុននីមួយៗមិនអាចមើលឃើញទិន្នន័យគ្នានោះឡើយ។
- **ការរក្សាដំណើរការក្រៅបណ្តាញ**៖ ត្រូវប្រើប្រាស់អង្គចងចាំមូលដ្ឋានក្នុងកម្មវិធីរុករក ដើម្បីផ្ទុកទិន្នន័យមុខទំនិញ និងតម្លៃ សម្រាប់ឱ្យច្រកលក់រាយអាចដំណើរការលក់បានទោះបីដាច់សេវាអ៊ីនធឺណិតរហូតដល់ 72 ម៉ោង។

### 2. អនុសាសន៍ផ្នែកអាជីវកម្ម និងការកំណត់តម្លៃ (Commercial & Pricing Model)
- **ការលក់កញ្ចប់ប្រចាំឆ្នាំ**៖ លើកទឹកចិត្តឱ្យអតិថិជនបង់ប្រាក់ជាកញ្ចប់ប្រចាំឆ្នាំ ដោយផ្តល់ការបញ្ចុះតម្លៃ 20% (បង់ 10 ខែ ថែម 2 ខែឥតគិតថ្លៃ) ដើម្បីទទួលបានលំហូរសាច់ប្រាក់មុន និងរក្សាអតិថិជនបានយូរអង្វែង។
- **ការផ្គួបជាមួយឧបករណ៍រឹង (Hardware Bundling)**៖ សហការជាមួយក្រុមហ៊ុនផ្គត់ផ្គង់ឧបករណ៍រឹង ដើម្បីលក់កញ្ចប់ពេញលេញ (ម៉ាស៊ីន POS + ម៉ាស៊ីនព្រីន 80 មីលីម៉ែត្រ + ម៉ាស៊ីនស្កេនបាកូដ + ថតលុយ) ជួយឱ្យអតិថិជនមិនបាច់ចំណាយពេលដើរទិញដោយខ្លួនឯង។
- **កម្មវិធីណែនាំអតិថិជនបន្ត (Referral Program)**៖ ផ្តល់កម្រៃជើងសារជូនគណនេយ្យករ ទីប្រឹក្សាអាជីវកម្ម ឬអតិថិជនចាស់ ដែលបានណែនាំអាជីវកម្មថ្មីមកប្រើប្រាស់ប្រព័ន្ធ។

### 3. អនុសាសន៍ផ្នែកប្រតិបត្តិការ និងការផ្លាស់ប្តូរ (Change Management & Training)
- **ការដាក់ឱ្យប្រើប្រាស់ជាដំណាក់កាល (Phased Rollout)**៖ ជៀសវាងការដាក់ឱ្យប្រើប្រាស់គ្រប់មុខងារទាំងអស់ក្នុងពេលតែមួយ។ ត្រូវអនុវត្តជា 3 ជំហាន៖
  - ជំហានទី 1៖ ច្រកលក់រាយ និងការគ្រប់គ្រងស្តុក
  - ជំហានទី 2៖ ការបញ្ជាទិញចូល លទ្ធកម្ម និងវិក្កយបត្រ
  - ជំហានទី 3៖ គណនេយ្យទ្វេបញ្ជីពេញលេញ និងបន្ទប់តាំងបង្ហាញឌីជីថល Showroom
- **ការជ្រើសរើសបុគ្គលិកស្នូល (Internal Champion)**៖ ត្រូវបណ្តុះបណ្តាលបុគ្គលិកដែលមានភាពវៃឆ្លាតម្នាក់ឱ្យក្លាយជាអ្នកជំនាញផ្ទៃក្នុងប្រចាំក្រុមហ៊ុនរបស់អតិថិជន ដើម្បីជួយដោះស្រាយបញ្ហាបន្ទាន់ដល់មិត្តរួមការងារ។

### 4. អនុសាសន៍ផ្នែកសន្តិសុខ និងសវនកម្ម (Security & Governance)
- **ការហាមដាច់ខាតការប្រើប្រាស់លេខសម្ងាត់រួមគ្នា**៖ បុគ្គលិកម្នាក់ៗត្រូវមានគណនី និងលេខសម្ងាត់ផ្ទាល់ខ្លួនជានិច្ច ដើម្បីងាយស្រួលតាមដានអ្នកទទួលខុសត្រូវ។
- **ការគ្រប់គ្រងការបញ្ចុះតម្លៃ និងការលុបវិក្កយបត្រ**៖ រាល់ការបញ្ចុះតម្លៃលើសពីកម្រិតកំណត់ (ឧទាហរណ៍ លើសពី 10%) ឬការលុបវិក្កយបត្រចោល ត្រូវតែតម្រូវឱ្យមានការអនុម័តពីអ្នកគ្រប់គ្រង និងកត់ត្រាក្នុងកំណត់ហេតុសវនកម្មជានិច្ច។
